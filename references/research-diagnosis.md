# 数字化转型调研报告方法

整理自用户提供的《数字化转型调研报告撰写指南》。原文未附可核对的来源；本文件将通用调研方法转为操作流程，将机构方法、模型名称和指标数量保留为待核实线索。

## 1. 核心逻辑与六步流程

遵循「诊断—对标—定位—建议」：外部环境分析与内部现状诊断 → 差距分析 → 需求识别 → 改进建议。业务现状先于IT能力评估，避免把企业问题直接等同于系统缺失。

| 步骤 | 核心工作 | 产出 |
|---|---|---|
| 锚定目标 | 对齐战略，将经营诉求转为可验证的诊断问题 | 目标与诊断问题表 |
| 划定范围 | 明确业务域、组织、地域、系统、时间与排除项 | 调研边界与样本计划 |
| 分层诊断 | 从业务流程到系统、数据、设施、管控逐层收集证据 | 现状台账与证据索引 |
| 深度分析 | 按维度—指标—根源拆解，比较目标与现状 | 差距与根因假设清单 |
| 输出结果 | 区分事实、受访者意见、分析判断和待验证事项 | 结构化报告及三张清单 |
| 监督改进 | 明确责任、期限与复核方式，跟踪实际变化 | 诊断—改进—再诊断记录 |

## 2. 调研方法与证据采集

| 方法 | 使用方式 | 需要记录的边界 |
|---|---|---|
| 问卷调查 | 按管理层、业务、IT及一线岗位设计问题，收集大范围反馈 | 发放数、有效数、回收率、岗位/部门覆盖、缺失和重复处理 |
| 内部访谈 | 访谈领导、业务负责人、IT负责人及实际使用人员，追问案例、频次与影响 | 角色、日期、原意摘要、证据线索；受访意见不自动成为已证实事实 |
| 专题研讨/设计思维 | 跨部门梳理流程、冲突与需求，形成共识 | 已达成共识、分歧、决策责任人与待验证动作 |
| 资料研究与分析 | 检查战略文件、制度、系统清单、流程记录、数据字典与运行数据 | 来源、版本、时间覆盖、适用范围及局限 |
| 专家访谈 | 获取行业趋势和标杆方法，检验方案适配性 | 专家背景、时间、观点与事实的区分，不把个体观点当行业统计 |

必要时经用户授权开展现场观察或抽样核验，将实际流程与制度、访谈和系统记录交叉比对。企业调研数据不发送给公开资料搜索接口；公开检索仅用通用行业和主题词。

问卷条目包含：`问题编号｜对应目标/维度｜适用角色｜问题｜选项或单位｜统计周期｜需佐证的材料｜不适用/不知道选项`。围绕单一可观察事实提问，避免把“有系统”和“系统有效”混为一项；自评结果只能作为初步线索。未知、不适用和未回答分别记录，不一律算零分。

访谈提纲围绕：经营目标 → 真实流程和例外 → 痛点案例 → 影响规模 → 系统和数据限制 → 已尝试措施 → 根因假设 → 改进约束。报告引用时使用角色或匿名编号，按用途减少个人信息。

维护证据表：`证据编号｜来源/角色｜日期与覆盖期｜对象/范围｜记录或数据位置｜观察事实｜局限｜关联发现编号`。同一说法的多次转述不算独立证据。材料冲突时列出差异及核验动作，不擅自选取有利结论。

## 3. 业务现状与四维评估

先解读总部管理职能、下属单位运营职责与各业务领域，形成业务能力总体框架；小企业按实际部门/岗位裁剪，不虚构集团组织。

业务与IT详细调研可依次执行：业务系统盘点 → 业务流程梳理 → 流程分解 → 业务关系梳理 → 数据标准梳理 → 数据分类分级。按需输出系统清单、流程图、职责关系图、数据流图、数据字典与分类分级清单；分类分级依据须明确，不能凭猜测认定法定等级。

| 评估维度 | 覆盖内容 | 典型核验点 |
|---|---|---|
| 信息系统支撑 | 业务支撑度、技术支撑度、数据资源、组织覆盖、信息集成 | 在用/在建/拟退出系统、实际使用情况、重复录入、接口与流程断点 |
| 数据资源治理 | 指标、业务数据、主数据、元数据、标准、质量、安全、组织与平台 | 编码/口径一致性、责任人、质量抽样、共享权限与变更记录 |
| 基础设施建设 | 公用技术平台、网络、数据中心、云、灾备、安全、桌面与运维 | 容量/可用性、恢复验证、运维记录与适用的IT/OT边界 |
| 信息化管控 | 管控能力、模式、组织、标准、流程、人才与文化 | 立项与验收职责、投入/价值管理、高管认知、人员能力及变革阻力 |

每一发现说明对应业务影响，按「现象 → 指标/证据 → 根因或待验证假设 → 改进方向」展开。根因不足以确认时列下一步验证，不因访谈中有人归咎某部门就认定其为根因。

## 4. 成熟度模型选择与定量边界

用户原文提供以下候选线索，实际使用前应读取模型发布方原始材料，核对名称、版本、维度、评分规则、适用行业与使用条件：

| 候选线索 | 原文描述的关注点 | 必须核实的部分 |
|---|---|---|
| DLMM | 规范、场景、领域、平台、生态五阶段，十个水平档次 | 阶段与档次映射、交叉区间及与GB/T 45341—2025等标准的关系 |
| SKOTT | 战略、KPI、组织、算力/数据/算法、人才 | 维度定义、权重、三个层次的划分规则 |
| 中国联通模型 | 战略引领、服务创新、运营协同、能力支撑、价值实现 | 原文所述19项二级/48项三级指标、L1至L5及问卷版本 |
| 华为评估模型 | 愿景、目标、应用、技术、组织、资金、人才等 | 原文所述12维度/29项指标的出处与适用对象 |
| IOMM | 原文将其作为业务现状分析的参考 | 标准全称、发布主体、版本与实际适用范围 |

奇点云“360°数据管家”、数字生态指数“15套问卷”、2025调研的价值/技术双维度，以及联通、埃森哲、京东的方法归因也只是检索线索。不凭这些描述重建其专有问卷、官方算法或声称已完成该机构评估。

选一个适合本次目标的主模型，不拼接不同模型的分数或等级。正式量化应披露：模型版本、指标及评分锚点、权重、证据映射、缺失/不适用处理、计算过程和评级阈值。权重与缺失处理按所选模型执行，不能自行补齐官方规则。

缺少模型原文、规则或企业证据时，采用有依据的定性诊断并标注「初步判断/待评估」，不输出官方等级。用户需要自定义评分时，可构建明确标为顾问自定义的透明量表，说明评分依据、聚合方式与局限，不冒充任何标准认证。

行业对标须核对行业、规模、业务模式、时期、样本及指标口径的可比性。没有可比数据时写「暂无可验证对标数据」；不得虚构全国均值、百分位、领先比例或排名。只有定性材料时用差距表，不画带虚假分数的雷达图。

## 5. 调研报告结构

完整报告使用以下八章；简版可合并章节。没有实测资料时保留待填项，并在标题和开头明确是模板或初步诊断。

1. **项目背景与调研概述**：背景、目的、范围、对象、方法、技术路线、调研时间、样本覆盖、数据来源与限制。
2. **企业基本情况**：规模、业务板块、组织、战略定位、发展目标与主营业务。
3. **环境分析与战略解读**：宏观/行业环境、上级或企业战略、相关技术趋势及可比标杆。
4. **业务现状分析**：各领域职能、流程、能力框架、现状问题与核心痛点。
5. **信息化/数字化现状评估**：按系统支撑、数据治理、基础设施、信息化管控四个维度展开，并关联证据。
6. **成熟度评估**：模型与方法、证据覆盖、可计算的维度结果、综合评级条件、对标与定位；条件不足时说明待评估内容，不硬凑定量结论。
7. **差距分析与核心问题诊断**：目标差距、短板、根因、影响与优先级问题清单。
8. **改进建议与转型方向**：分阶段目标、优先任务、投入方向、组织/人才/资金保障和复核机制。确有服务商选型需求时再提出能力要求与经核实的候选；未经授权不联系服务商。

附录按实际调研提供：问卷样本、访谈提纲与匿名记录摘要、数据统计方法、证据索引、行业对标数据与出处。没有实施问卷或访谈时只提供模板，不伪造记录。

## 6. 三张清单与规划衔接

| 清单 | 建议字段 |
|---|---|
| 差距清单 | 差距编号、业务目标、现状证据、目标能力、差距、根因/假设、业务影响、优先级及理由 |
| 任务清单 | 任务编号、关联差距编号、行动、交付物、责任角色、依赖、阶段、验收口径 |
| 投资清单 | 投资编号、关联任务编号、资源/费用类别、数量依据、估算或待询价、一次性/持续性、阶段 |

清单间使用稳定编号关联，一项投资服务多项任务时标共享范围避免重复计费。未知金额不得编造，投资口径衔接 [方案设计与项目口径](solution-design.md)。

每项优先行动给出责任角色、期限、改进指标和复核节点，形成「诊断—改进—再诊断」闭环。用户继续要求规划时，将三张清单转入 [数字化转型规划方法](planning-methodology.md)，保留证据编号和待验证事项，使架构和项目能回溯到调研发现。
